# Decision log

Standing until explicitly reversed. Newest first.

| Date | Decision | Why |
|---|---|---|
| 08-01 | **#15 spike: NO-GO on the Claude Agent SDK; adopt the SDK Tool Runner instead** (`client.beta.messages.tool_runner`, already in our `@anthropic-ai/sdk`). Reverses AGENT-PLAN §2. Order: server-side compaction/context-editing → move the round loop onto tool_runner (keeping `dispatchTool`) → per-call approval hooks. Full reasoning: `docs/AGENT-SDK-SPIKE.md`. | The Agent SDK ships Bash + local Read/Write/Edit — on the studio host that filesystem holds every app's delivery token, so importing it inverts our custody model and leaves the boundary standing on permission config rather than absence. The Tool Runner gives the loop, hooks, retries, streaming and real context management with **no built-in tools**, so the reachable capability set stays exactly what we grant. |
| 07-31 | **Secret ownership map** (operator asked whether envs force XVibe to own secret management): split **authority** from **custody**. Pluggie keeps authority — mints/revokes/scopes all platform + delivery tokens, and owns connector-credential custody (07-30 decision). XVibe keeps **edge custody only** — delivery tokens in `secret.json`, injected by the `/api/v1` proxy; envs just put a dev token beside the prod one under the same seam. The single future XVibe-**owned** store: **per-app function env-vars when #17 ships** — secrets must live where the runtime is, and the runtime layer is ours: per-env (dev/prod), write-only UI (set, never read back), encrypted, bound at deploy through the `xvibe/runtime` shim + `RuntimeTarget` (so a runtime swap carries them — exit insurance holds). End-user credentials stay banned everywhere (Clerk only). | Each secret lives at the layer that uses it; XVibe owns nothing new until it owns a runtime layer — then it owns exactly that layer's env vars and nothing more. |
| 07-31 | **Planning layer = backlog → sprints → parallel tasks** (operator: "I don't want to copy Replit, I want to do it better") — productize the PM model we run in docs/pm: a groomed per-app **backlog**; agent-assisted **sprint planning** where the agent proposes sprint scope, splits it into tasks, **predicts collisions from each task's planned file/schema footprint and parallelizes only disjoint work**; tasks execute on full-codebase copies (tree design below); sprint closes with an agent-written review (shipped / checkpoints / cost). | The agent as PM copilot with planning-time conflict *avoidance* (on top of merge-time resolution) is the do-it-better edge — Replit has tasks, not a product-management layer. |
| 07-31 | **Dev/prod environments (operator building this with Pluggie) become the data split**: task previews run against the **dev** environment; main/live runs against **prod**. In dev, ALL schema ops apply immediately — task previews are full-fidelity, mutations included. A task's merge turn **promotes** its schema changes to prod as the approved diff. Supersedes "additive live / mutating deferred" once envs land. Remaining gap: parallel tasks share dev — per-task isolation is still the Neon-branch endgame. | Data split at the platform layer, where it belongs; prod is never touched by an unmerged task; serialized merges keep prod safe regardless. |
| 07-31 | **Task trees v2 (operator design — supersedes "one active task per app")**: every task gets an **independent byte-copy of main** and **its own live preview** (`<app>--t<n>.<domain>` on the existing wildcard; `--` reserved in app slugs as the separator). **Merges serialize through a queue to main, one task at a time**: disjoint files auto-merge; overlapping files get an agent semantic-merge (base + both diffs + both task intents), then the quality gate + a diff/preview before landing as a new checkpoint. Open tasks keep their base and rebase the same way at *their* merge turn. **Shared-backend caveat until Neon branching**: additive schema ops apply live immediately (safe for all previews); mutating/destructive schema ops are deferred and land as an approved dry-run diff at merge time. | Parallel exploration without merge hell; copies are cheap directories, previews are free on wildcard DNS, and the serialized queue means conflict handling is always a two-sided problem, never N-way. |
| 07-31 | **P0 approved (Sonnet build tier)** + **model selector in the studio: Claude tiers only (Haiku/Sonnet/Opus), default "Auto"** — a router picks the tier per request (quick edit vs full build vs plan); the user can pin. **Multi-provider (non-Claude) models: parked, revisit eventually.** | Operator ok'd the cost; auto-routing spends the big model only where it pays; provider abstraction later is a swap behind the same selector. |
| 07-31 | **"Agents" = specialized passes of one system, not separate personas**: Router → Builder (tier by route) → quality gate (static checks + fresh-context Reviewer) → checkpoint. **Merges are intent-replays, never text merges**: one active task per app; parallel tasks become variants; landing B after A = re-executing B's task prompt on A's result.
